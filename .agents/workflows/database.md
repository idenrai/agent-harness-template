# 데이터베이스 워크플로우

**트리거:** `/database` (또는 사용자가 명시적으로 데이터베이스 스키마 변경, 마이그레이션 생성, DB 설계를 요청할 경우)

**설명:**
데이터베이스 스키마는 한 번 잘못 변경되면 데이터 유실이나 런타임 에러 등 치명적인 결과를 낳을 수 있습니다. 이 워크플로우는 AI 에이전트가 데이터베이스 구조를 변경할 때 반드시 안전한 마이그레이션 절차를 밟도록 강제합니다.

---

## 1. 스키마 분석 (Schema Analysis)
- **목적:** 현재 데이터베이스 상태를 파악하고 변경 사항의 영향을 평가합니다.
- **액션:**
  - 기존 모델/스키마 파일(예: `schema.prisma`, `models.py`, `init.sql` 등)을 주의 깊게 읽습니다.
  - 이 변경이 기존 데이터베이스 내의 데이터에 미칠 영향을 분석합니다. (예: NOT NULL 컬럼을 새로 추가할 경우 기존 데이터에 대한 기본값 처리가 필요한가?)

## 2. 마이그레이션 전략 검토 (Migration Strategy)
- **목적:** 변경 사항을 코드로 작성하기 전에 마이그레이션 가이드라인을 참조합니다.
- **액션:**
  - 반드시 `.agents/skills/database-migration/SKILL.md` 스킬을 읽고 데이터베이스 마이그레이션 가이드라인을 준수합니다.
  - 업(Up) 마이그레이션 뿐만 아니라 다운(Down, 롤백) 마이그레이션 시나리오를 고려합니다.

## 3. 마이그레이션 코드 작성 (Migration Creation)
- **목적:** 안전한 형태의 마이그레이션 코드를 생성합니다.
- **액션:**
  - 프로젝트에 설정된 ORM(예: Prisma, TypeORM, SQLAlchemy) 또는 마이그레이션 툴(예: Flyway, Liquibase)의 방식에 맞춰 파일을 생성합니다.
  - 마이그레이션 적용 후 데이터 유실 위험(Data Loss Risk)이 있다면, 반드시 사용자에게 위험성을 경고하고 적용 전 백업(Backup)을 권고하십시오.

## 4. 검증 (Validation)
- 작성된 마이그레이션 스크립트를 사용자에게 설명하고, 로컬 환경에서 실행(Run)해 볼 수 있도록 커맨드를 제공합니다.
